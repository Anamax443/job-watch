Information flow

How a job ad travels from source to human — and above all who decides at each step. Blue is code: deterministic, testable, repeatable. Amber is the model: judgement that has to be measured. The whole point of the design is to keep the amber boxes few, and to let none of them have the last word.

The journey of one ad

code — deterministic, testable, last word model — judgement, measured by evals output — out of the agent

What follows from this

The model has one job To judge how well an ad matches the profile. Everything else — source selection, prefilter, deduplication, region, threshold, caps, writes, sending — is done by code. The model has no direct access to any irreversible action: it returns a number and a sentence; what happens with them is up to the code.
Third-party text never acts as instructions The ad description is written by an employer or an agency. It enters the prompt wrapped in <inzerat>, a closing tag inside the input is neutralised, and the system prompt states that there are no instructions inside.
The brake sits after the model, not in the prompt The region rule started as a mere sentence in the prompt — and the weak model ignored it: a Prague ad scored 80/100 with the reasoning that Prague is in the preferred region. Now the region is derived deterministically from the location text and the score is capped.
Nothing is lost silently What is not scored in time waits in the queue. What fails returns null, not zero. What has an unverifiable location passes with a ⚠ instead of being dropped. A crashed run sends a message through the same channel as a find.
The only amber box with real power is scoring — and that is exactly why it is the only one with its own measurement. Until that number existed, the quality of the agent was a matter of opinion.
